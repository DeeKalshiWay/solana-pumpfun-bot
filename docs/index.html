What this project demonstrates

  • Real-time async pipeline. One PumpPortal WebSocket fans out via pub/sub to 8 detector modules. No duplicate connections, no rate-limit waste.
  • Reliability hygiene. Atomic JSON writes (write-temp + os.replace), PID lockfile, watchdog auto-restart, WS rate-limit backoff with jitter, log rotation + gzip.
  • Adaptive risk engine. Kelly-lite sizing, multi-tier circuit breakers, trailing stops with regime switch, no-movement and time exits.
  • Persistence. sqlite trade log with indexed columns + raw-JSON forward-compat column. Dual-write transition keeps the legacy JSONL authoritative until cutover.
  • Observability. aiohttp dashboard at :8765, 7 REST endpoints, hourly equity snapshots, single-page SPA.
  • Test + lint floor. ruff + mypy + pytest + Docker build smoke on every push (GitHub Actions). 23 / 23 green.
  • Two deployment paths. Docker compose for any Linux host, or systemd unit + idempotent installer for bare-metal.

Where the edge comes from

1. ADAPTIVE POSITION SIZING (KELLY-LITE)

Rolling 20-trade win rate scales position size: 0.6× when cold (≤30% WR), 1.0× normal, 2.0× when hot (≥55% WR). Captures more SOL during momentum stretches, less during regime shifts. Hard cap at 2.5× to prevent ruin.

2. MOONSHOT-OPTIMIZED TAKE-PROFIT LADDER

Sells small slices at +75% / +300% / +800%, keeps final 30% riding the trailing stop with no upper cap. Trailing widens to 35% from peak once peak exceeds +100% so power-law winners aren't clipped on normal pullbacks.

3. COUNTERFACTUAL LOOP — OBSERVABILITY, NOT VALIDATION

Every rejected token gets re-polled 10 min later for market-cap delta and exit reason. Useful as observability — it shows what each filter is killing. Not a held-out validation: pump.fun’s base rate is >95% rug, so any filter looks “validated” against an unfiltered universe. The honest experiment splits train/test and checks whether rejects underperform the base rate on a held-out set. Tracked as future work in the README.

4. CIRCUIT BREAKERS

Three independent layers: 6 consecutive losses → 10 min pause, −25% day → halt until UTC midnight, −40% lifetime → emergency stop. Fired 5 times overnight, each preventing what would have been deeper losses during regime shifts.

Production reliability

  • Single-instance enforcement via PID lockfile — duplicate launches refuse with exit code 2
  • Atomic JSON writes (write-temp + os.replace) so file corruption is impossible mid-crash
  • Watchdog auto-restart with exponential backoff on rapid crashes
  • WS rate-limit handling — exponential backoff up to 5 min on HTTP 403
  • Log rotation with gzip (20 MB threshold, 5-rotation ceiling)
  • Counterfactual file auto-trim at 5 MB to bound disk usage
  • Crash-safe state — closed trades, creator leaderboard, paper wallet all persist

Limitations

The paper sim is up 100× on a realistic-friction model — that is a real result inside the simulator. Whether it survives a move to real money is unknown, and there are honest open questions worth flagging:

  • Live performance unverified. The friction simulator (size-dependent slippage, MEV tax, ~5% tx-fail rate, network fees) is closer to live than the legacy 1.5% flat slip was, but there is still no live data. Paper PnL is paper PnL until real capital is traded.
  • Counterfactual loop — observability, not validation. Re-polling rejected tokens 10 min later is a useful signal for what each filter is killing. It is not held-out validation: pump.fun’s base rate is ~95% rug, so beating the rejects does not prove beating the base rate. A held-out train/test split is future work.
  • Some thresholds are tuned to the trade history. The TP ladder (75 / 300 / 800 %) and the 4-min time exit are partly motivated by pump.fun dynamics and partly chosen by inspecting closed-trade outcomes. They would need re-tuning for a different market regime.
  • Concentration risk in the top tickers. Per the sqlite trade log: OHIO alone is 41.9% of total PnL across 20 catches; the top 3 tickers are 67.7%; the top 5 are 79.2%. When 80% of paper PnL comes from five names, the result reflects “compounded well in five lucky tickers” more than “broad edge across pump.fun.”
  • Hot-streak 2× sizing is a regime bet. Reasonable when memecoin regimes persist for hours, weaker when winners are i.i.d. The 2.5× cap limits ruin in either case.

The portfolio value of this project is the systems engineering: async pipeline, dual-write persistence, CI / Docker / systemd floor, observability stack. The trading layer is a working test bed for that engineering.
